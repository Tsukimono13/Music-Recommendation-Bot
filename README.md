# MusiGem

Telegram-бот для поиска музыкальных рекомендаций. Пользователь пишет запрос (артист, жанр, комбинация) — бот подбирает похожих исполнителей. Использует бэкенд с данными Last.fm, MusicBrainz, Spotify и моделью Gemini (Google) для разбора запроса.

---

## Возможности

| Кнопка / раздел | Описание |
|-----------------|----------|
| 🎸 Подобрать артистов | Ввод запроса (артист, теги или комбинация) → рекомендации с разбивкой по релевантности |
| ⛏️ Копнуть глубже | Дополнительные артисты порциями по 9 (до 2 нажатий) |
| 📤 Поделиться результатом | Переслать рекомендации друзьям через Telegram |
| 🪪 О проекте | О боте и команде |
| ❓ FAQ | Ответы на частые вопросы |
| 📻 Новости | Ссылка на канал [@MusiGemBotNews](https://t.me/MusiGemBotNews) |
| 🍩 Поддержать | Поддержка проекта (DonationAlerts, QR) |
| 📋 Отправить фидбэк | Идеи, багрепорты (в канал) |

Дополнительно:
- **Inline mode** — прямо в любом чате: `@musigem_bot radiohead`, `@musigem_bot finnish metal`, `@musigem_bot queen но больше фанка`
- Защита от флуда + отдельный rate limit для рекомендаций (3 запроса/мин)
- Ежедневный «факт дня» в 10:00 МСК
- Graceful degradation при недоступности Spotify
- Метрики запросов для админов (`/metrics`)

---

## Стек

- **Node.js** + **TypeScript**, **tsx**
- **Telegraf** (Telegram Bot API)
- **Upstash Redis** — персистентные сессии, пользователи, метрики, факты дня
- **node-cron** — планировщик фактов дня
- Внешний **бэкенд-API** для рекомендаций (`POST /api/music/recommend`)

## Переменные окружения

| Переменная | Описание |
|------------|----------|
| `TELEGRAM_BOT_TOKEN` или `BOT_TOKEN` | Токен бота от [@BotFather](https://t.me/BotFather) |
| `BACKEND_URL` | URL бэкенда с рекомендациями (обязательно) |
| `UPSTASH_REDIS_REST_URL` | URL Upstash Redis (для сохранения данных между рестартами) |
| `UPSTASH_REDIS_REST_TOKEN` | Токен Upstash Redis |
| `FEEDBACK_CHANNEL_ID` | ID канала для фидбэков (например `-1001234567890`) |
| `ADMIN_IDS` | ID админов через запятую (для `/stats`, `/metrics`) |
| `WEBHOOK_URL` | Публичный URL сервиса для webhook. **Не задавать** — бот работает в long polling |
| `PORT` | Порт HTTP-сервера (webhook, health, cron). По умолчанию `3000` |
| `CRON_SECRET` | Секрет для вызова крон-эндпоинта (`/cron/daily-fact?secret=...`) |

Пример: см. `.env.example`.

## Запуск

```bash
npm install
```

- **Локально (long polling):** задать `BOT_TOKEN`, `BACKEND_URL` → `npm run dev`
- **Деплой (webhook):** задать `WEBHOOK_URL` (полный URL сервиса). Бот выставит webhook при старте и включит self-ping для предотвращения засыпания Render free

Без Redis всё работает (fallback на JSON-файлы), но данные не переживут рестарт.

## Админ-команды

| Команда | Описание |
|---------|----------|
| `/stats` | Количество пользователей |
| `/stats list` | Список пользователей |
| `/metrics` | Метрики запросов: топ запросов, среднее время, ошибки, таймауты |

Доступны только пользователям из `ADMIN_IDS`.
